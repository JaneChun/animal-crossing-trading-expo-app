# 바텀시트 UI 버그 4건 수정 - 명세

## 화면/기능 흐름

### #62 댓글 수정 시트 취소

- 댓글 수정 시트가 열린 상태: 왼쪽 상단 `취소` 탭 → 수정 내용은 저장되지 않고 시트가 닫힌다. 화면은 게시글 상세에 그대로 머문다.
- 답글 수정 시트(제목 `답글 수정`)도 같은 방식으로 동작한다.
- 키보드가 올라온 상태에서도 `취소`가 한 번에 눌리고 시트가 닫힌다.
- 시트 헤더의 왼쪽·오른쪽 버튼은 제목 영역과 겹쳐도 항상 눌린다. 신고 시트 2단계의 `이전` 버튼도 같다.
- 취소한 뒤 같은 댓글의 수정 시트를 다시 열면, 수정하던 내용이 아니라 원래 댓글 내용이 표시된다.

### #56 키보드를 내린 뒤 시트 높이

- 시트 안의 입력창 포커스 → 키보드가 올라오면서 시트가 키보드 위로 올라간다(기존 동작 유지).
- 키보드가 내려감(키보드 툴바의 완료, 입력창 바깥 탭 등) → 시트가 키보드를 올리기 전의 스냅 포인트 높이로 돌아온다. 가격 수정 시트는 `55%`이다.
- 가격 수정 시트에서 키보드가 올라오면 시트가 화면 높이까지 펼쳐져, 가격·개수 입력과 총계가 키보드 툴바 위에 모두 보인다. 원래 높이로는 키보드 툴바(50pt)에 총계가 가려지기 때문이다. 키보드가 내려가면 55%로 돌아오고, 사용자가 손으로 시트를 더 크게 끌어올릴 수는 없다.
- 사용자가 시트를 드래그하는 중에 키보드가 내려가면, Gorhom이 복구를 건너뛰고 드래그 결과를 따른다.

### #57 일괄 추가 검토 화면

- 본문에 여러 줄 붙여넣기 → `아이템 찾기` → 로딩 → 검토 화면이 표시된다.
- 검토 화면에서는 결과 목록만 스크롤되고, 하단의 `{N}개 추가하기` 버튼(과 용량 초과 경고)은 항상 시트 안에 보이며 누를 수 있다.
- 결과가 한두 개일 때와 화면을 넘길 만큼 많을 때 모두 같다.
- 버튼은 하단 inset(Android 3버튼 내비게이션 바, iPhone 홈 인디케이터) 위로 8pt 띄워 표시된다.

### 공통: 시트 하단

- 모든 시트의 내용은 지금 화면에 보이는 시트 영역 안에서 끝난다. `['95%', '100%']` 시트가 95%에 있을 때도 같다. 배경: Gorhom 내용 영역을 그대로 채우던 공통 시트 루트가 하단을 화면 밖으로 밀어내던 것이 #57의 원인이었다.
- 키보드가 없으면 시트 맨 아래를 하단 inset만큼 비워 내비게이션 바·홈 인디케이터에 내용이 가려지지 않는다.
- 키보드가 있으면 내용이 키보드 툴바 위에서 끝난다. 프로필 수정·댓글 수정처럼 `KeyboardAwareScrollView`를 쓰는 시트는 스크롤 뷰가 키보드 여백을 직접 넣는다.
- 가격 수정 시트는 55% 높이로 열려 이름·색상·가격·개수·총계가 iPhone SE에서도 보인다.

### #71 신고 시트

- 1단계(신고 사유): 사유 5개(사기 ~ 기타)가 모두 보이거나, 시트 본문을 스크롤해 마지막 `기타`까지 선택할 수 있다.
- 2단계(상세 내용): 입력창 포커스로 키보드가 올라와도 입력창, 안내 문구, 헤더의 `이전`·`제출` 버튼이 가려지지 않는다.
- 게시글, 댓글·답글, 채팅방 메뉴, 다른 사용자 프로필의 네 진입 경로에서 같은 모달이 같은 방식으로 동작한다.

## 상태 정의

| 상태 | 설명 |
| ---- | ---- |
| 시트 기본 위치 | `snapPoints`의 현재 인덱스에 해당하는 높이 |
| 키보드 임시 위치 | 키보드가 올라와 시트가 키보드 위로 밀려 올라간 위치. 키보드가 내려가면 기본 위치로 돌아가야 한다 |

## 엣지 케이스

- 시트가 키보드가 올라온 상태에서 열림(#57의 붙여넣기 직후): 키보드가 내려간 뒤 시트는 기본 위치에 있어야 하고 하단 버튼이 가려지지 않는다.
- 입력창이 없는 시트(`AddVillagerModal` 등): 키보드 복구 설정이 추가되어도 여닫기와 드래그 동작은 그대로다.
- 신고 시트에서 2단계 → `이전`으로 1단계에 돌아옴: 선택했던 사유가 그대로 선택되어 있고, 목록 스크롤이 정상 동작한다.
- 작은 화면(iPhone SE)과 하단 inset이 있는 화면 모두에서 위 동작이 같다.
