# UI 버그 수정 (#73–#78) - 명세

## 화면/기능 흐름

- 새 글 작성·글 수정(`Boards`, `Communities`), 다크 모드: 제목·본문에 입력 → 글자가 `text.primary` 색으로 보인다. 라이트 모드에서는 기존과 같은 색으로 보인다.
- 새 글 작성, 키보드 열림: 제목·본문 입력창을 탭 → 포커스된 입력창이 키보드 툴바 위로 스크롤된다.
- 새 글 작성, 본문 입력 중: 줄바꿈으로 본문이 키보드 위 영역보다 길어짐 → 화면이 커서를 따라 스크롤되어 입력 중인 줄이 키보드 툴바 위에 보인다.
- 새 글 작성, 키보드 열림: 하단 버튼 영역(`아이템 추가`·`등록`)은 iOS·Android 모두 화면 하단에 고정되어 키보드에 가려진다. 키보드를 내리면 원래 위치(하단 inset 위)에 보인다.
- 새 글 작성, 유효성 오류: `등록` 탭 → 폼이 맨 위로 스크롤된다(기존 동작 유지).
- Android 액션 시트: `⋮` 메뉴·게시판 선택·프로필 이미지 변경 메뉴를 열면 → 마지막 항목(`취소`·`닫기`)까지 내비게이션 바 위에 보이고 누를 수 있다. 시트 아래 여백은 `insets.bottom`이다.
- iOS 액션 시트: 기존과 같다.
- 댓글·채팅에서 연 프로필: 작성 글 목록을 끝까지 스크롤 → `마지막 글입니다.`가 내비게이션 바(또는 홈 인디케이터) 위에 보인다.
- 하단 탭의 프로필: 목록 끝 여백이 기존과 같다(탭바 위에 여백이 추가로 생기지 않는다).
- 프로필 수정 시트(Android): 입력창 위에 손가락을 대고 끌면 → 시트 내용이 스크롤된다. 드래그를 놓아도 다른 입력창으로 포커스가 옮겨 가지 않는다.

## 상태 정의

| 상태 | 설명 |
| --- | --- |
| 탭 안 프로필 | 하단 탭 `ProfileStackNavigator`에서 연 `Profile`. 탭바가 하단 inset을 처리한다 |
| 스택 프로필 | 댓글·채팅 등에서 `RootStack`의 `Profile`로 연 화면. 화면이 직접 하단 inset을 처리해야 한다 |

## 엣지 케이스

- 하단 inset이 0인 기기(iPhone SE): 액션 시트·프로필 목록에 여백이 추가되지 않는다. 새 글 작성 하단 버튼은 기존의 최소 여백(`Spacing.s`)을 유지한다.
- Android 제스처 내비게이션 모드: `insets.bottom`이 작으므로(약 16) 여백도 그만큼만 생긴다.
- 새 글 작성에서 키보드가 열린 채 아이템 추가·주민 추가 모달을 열고 닫을 때: 스크롤 위치가 어긋나거나 빈 여백이 남지 않는다.
- 프로필 수정 시트에서 입력창을 짧게 탭할 때: 기존처럼 그 입력창에 포커스된다.
- iOS 새 글 작성 본문: 행간이 26이라 커서가 글자보다 조금 위에 그려진다. React Native가 iOS에서 글자만 줄 가운데로 옮기고 커서는 옮기지 않기 때문이며, 네이티브 패치 없이는 고칠 수 없어 이번 범위에서는 보류한다.
- Android 댓글 수정 시트: 여러 줄 입력칸 안을 끌어 스크롤할 수 없다(이번 변경 전부터 있던 동작). 입력칸을 RN `TextInput`으로 바꾸면 커서가 키보드 아래로 내려가므로 이번 범위에서는 고치지 않고 #84로 분리했다.
- Android 내비게이션 헤더(스택에서 연 프로필, 새 글 작성, 설정 등): 앱 루트 `SafeAreaView`와 react-native-screens 헤더가 상태바 높이를 두 번 넣어 헤더가 약 31dp 내려와 보인다. 앱 전체 헤더에 걸린 문제라 이번 범위에서는 고치지 않고 #85로 분리했다.
