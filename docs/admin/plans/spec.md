# 앱 내 관리자(어드민) 기능 - 명세

## 화면/기능 흐름

### 진입

- 관리자 계정(`Users.role == 'admin'`): 설정 화면 → "관리자" 섹션의 항목 → 어드민 홈
- 일반 계정: 설정 화면에 관리자 섹션이 보이지 않는다.
- 일반 계정이 딥링크로 어드민 화면에 들어온 경우: 화면을 그리지 않고 뒤로 돌아간다. 규칙에서도 읽기가 거부된다.
- 어드민 홈 메뉴: 운영(신고 관리 / 검토 필요 유저 / 에러 내역), 사용 현황(일별 통계 / 유저), 개발(디자인 시스템). 미처리 개수는 표시하지 않는다.

### 신고 내역

- 목록: 최신 신고(`createdAt`)가 위에 온다. 탭은 "접수"(`resolved == false`, 기본) / "처리완료"(`resolved == true`)다.
- 목록 항목: 신고 유형(`REPORT_CATEGORIES`의 KR) 배지와 그 옆 대상 종류 칩(게시글·댓글·답글·채팅·프로필), 신고 시각, 상세 내용 2줄, 신고자 → 피신고자 닉네임
- 검토 필요 유저: 어드민 홈에서 들어가는 별도 화면(`AdminReviewUsers`). `Users.report.needsAdminReview == true`인 유저를 정지 기한 칩과 함께 보여 주고, 항목을 누르면 유저 상세로 이동한다.
- 신고 상세에서 보이는 정보: 신고자, 피신고자, 유형, 상세 내용(`detail`), 신고 시점 스냅샷(제목·본문을 표시하며, 저장은 대상 문서 전체), 피신고자의 정지 상태(`suspendUntil`)와 누적 신고 수
- 원문 이동
  - 게시글 신고이고 원문 `status`가 `active`인 경우: "원문 보기" → `PostDetail`
  - 댓글 신고인 경우: "원문 보기" → 댓글이 달린 게시글의 `PostDetail`
  - 채팅 신고인 경우: "대화 보기" → `AdminChatViewer`
  - 프로필 신고인 경우: "프로필 보기" → `Profile(userId)`
- 처리 액션
  - "처리 완료": `resolved = true`. 완료된 신고는 "미처리" 탭에서 사라진다. "미처리로 되돌리기"도 제공한다.
  - 정지 해제: 정지 중일 때만 "정지 해제"를 보여 준다. 연장·새 정지 버튼은 없다. `liftSuspension` 함수가 즉시 정지를 풀고, 정지 때 숨겨진 게시글도 바로 복구한다(관리자가 숨긴 글 제외).
  - 콘텐츠 숨김: 게시글은 `status = 'hidden'` + `hiddenByAdmin = true`, 댓글은 `hiddenByAdmin = true`. 숨긴 상태에서는 "숨김 해제"를 보여 준다. 답글 신고는 숨김을 지원하지 않는다.
  - 게시글 숨김 해제 시 작성자가 정지 중이면 관리자 숨김 표시만 지우고 게시글은 계속 숨긴다. 정지가 풀리면 다른 정지 숨김 글과 함께 다시 보인다. 댓글은 정지로 숨겨지지 않으므로 숨김 해제 즉시 보인다.
  - 숨기기와 정지 해제는 확인 창을 거친다.
  - 액션 중에는 버튼이 비활성이고, 실패하면 에러 토스트를 띄우고 화면 값은 바뀌지 않는다.

### 신고 알림

- 신고 문서가 생성되거나 재신고로 덮어써지면 `role == 'admin'`인 모든 유저에게 푸시가 간다.
- 관리자가 `resolved`만 바꾼 경우에는 푸시가 가지 않는다.
- 푸시 문구: 제목 "[관리자] 신고 접수", 본문 "{유형} · {대상 종류} · {상세 내용 앞 30자}". 예: "사기 · 채팅 · 거래 후 아이템을 안 주고 차단했어요". 재신고도 같은 문구다.
- 대상 종류 표기: 게시글 / 댓글 / 채팅 / 프로필
- 상세 내용이 비어 있으면 "{유형} · {대상 종류}"만 보낸다.
- 푸시를 누르면 해당 신고 상세(`admin/report/:reportId`)가 열린다.

### 신고된 채팅 열람

- 메시지를 시간순으로 보여 주며, 입력창·읽음 처리·실시간 갱신이 없다.
- 신고자 메시지는 오른쪽(민트 말풍선), 피신고자 메시지는 왼쪽에 둔다. 헤더에 두 사람의 아바타와 닉네임을 보여 준다.
- 관리자가 열람해도 참여자의 `unreadCount`·`isReadBy`는 바뀌지 않는다.

### 통계

- 일별 통계: 한 날짜씩 보여 주고 이전·다음 날짜로 이동한다(오늘이 마지막). 게시글(`Boards`+`Communities`)·댓글·답글·채팅 메시지·신규 가입(`Users.createdAt`)·리뷰(`Reviews`) 수를 카드로 보여 주고, 전날 대비 증감을 추세 아이콘으로 붙인다(증가 빨강, 감소 파랑, 변화 없음은 표시 안 함).
- 날짜 경계는 KST 0시다.
- 게시글 수는 그날 작성된 글 전체다. 이후 숨김·삭제 여부와 관계없이 센다.
- 지난 날짜 값은 한 번 받으면 앱을 끄기 전까지 다시 요청하지 않는다. 오늘 값은 화면에 다시 들어오면 1분이 지난 경우에만 다시 요청한다.

### 유저

- 목록: `lastActiveAt` 내림차순. 항목에 닉네임, 섬 이름, 최근 접속일, 정지 여부를 보여 준다.
- 목록 항목에는 정지·관리자 배지를 함께 보여 준다.
- 유저 상세: 여권 카드 → 계정(로그인 방식·이메일·가입일·마지막 로그인·마지막 접속·푸시 수신 여부) → 활동(게시글·댓글·답글·채팅방·메시지, "프로필 보기") → 거래 리뷰(받은 리뷰·만족·불만족) → 신고·차단(받은 신고·접수한 신고·차단당함·차단함, 검토 필요 배지, 정지 중이면 정지 해제). 받은 리뷰·받은 신고 전체 목록은 이번 범위에서 제외한다.
- 유저별 활동 수는 상세에 들어갈 때 그 유저만 계산한다.

### 에러 내역

- 목록: 최신 에러(`timestamp`)가 위에 온다. 항목에 메시지 첫 줄과 시각을 보여 준다.
- 항목을 누르면 `stack` 전체가 펼쳐진다.

### 디자인 시스템

- 토큰: 현재 테마의 색(semantic 이름과 값), 글자 variant 7종, `Spacing`, `BorderRadius`, `Shadow`
- 컴포넌트: `src/components/ui/`의 공통 컴포넌트를 주요 props 조합별로 보여 준다.
- 기기의 다크 모드 설정에 따라 그대로 보인다. 화면 안에서 테마를 전환하지 않는다.

### 신고 데이터 수집

- 게시글·댓글·답글을 신고하면 `onReportWritten` 함수가 신고 대상 문서 전체를 `snapshot`으로 복사한다. 이미지·거래 정보처럼 이후 수정될 수 있는 필드도 남긴다. 신고자가 내용을 조작하지 못하도록 앱은 `snapshot`을 쓰지 않는다.
- 원문 조회에 실패해도 신고와 관리자 알림은 그대로 처리된다. 이때 `snapshot`은 비어 있다.
- 같은 신고자가 같은 유저를 다시 신고하면 기존 문서를 덮어쓰고, `snapshot`과 대상 필드(`postId`·`commentId`·`replyId`·`chatId`·`collectionName`)도 새 신고 대상 기준으로 바뀐다. 이번 신고에 없는 필드는 지운다.
- 답글 신고는 `commentId`에 부모 댓글, `replyId`에 답글을 저장한다.
- 신고 모달의 상세 내용 입력칸 아래에 "원활한 신고 처리를 위해, 신고한 대화 내용은 운영진이 확인할 수 있습니다."를 표시한다.
- 개인정보 처리방침 제1조(처리 목적) 목록에 "신고 접수 시 신고 대상 게시글·댓글·채팅 내용 확인 및 운영정책 위반 조치"가 있다.

### 활동 시각 기록

- 로그인 상태로 앱을 실행하면(자동 로그인 포함) `Users.lastActiveAt`을 현재 시각으로 갱신한다.

## 상태 정의

| 상태 | 설명 |
| --- | --- |
| 미처리 신고 | `resolved == false`. 생성 시와 재신고 시 이 값이 된다 |
| 처리 완료 신고 | 관리자가 "처리 완료"를 누른 신고 |
| 검토 필요 유저 | 최근 30일 신고 7회 이상으로 함수가 `report.needsAdminReview = true`로 표시한 유저 |
| 정지 유저 | `report.suspendUntil`이 현재보다 미래인 유저 |
| 관리자 숨김 게시글 | `status == 'hidden'` 그리고 `hiddenByAdmin == true`. 정지 해제 복구 대상에서 제외된다 |
| 정지 숨김 게시글 | `status == 'hidden'`이고 `hiddenByAdmin`이 없음. 정지가 풀리면 `active`로 복구된다 |
| 관리자 숨김 댓글 | `hiddenByAdmin == true`. 일반 유저의 댓글 목록에서 빠지고, 달린 답글도 함께 보이지 않는다. 게시글 댓글 수에서도 빠진다 |
| 열람 가능 채팅 | 채팅 신고가 한 번이라도 들어와 함수가 `Chats.reportedAt`을 기록한 채팅방 |

## 엣지 케이스

- 원문 게시글이 숨김·삭제됨: 관리자는 상태와 관계없이 원문 링크를 보고 게시글 상세로 들어갈 수 있다. 링크 아래에 숨김·삭제 상태 안내를 표시한다. 관리자가 숨긴 글은 "숨김 해제"를 보여 준다.
- 관리자가 숨김·삭제된 게시글 상세를 열면 헤더 맨 위에 상태 배너(`ui/Banner`)를 보여 준다: "작성자가 삭제한 게시글"(danger), "관리자가 숨긴 게시글"·"계정 정지로 숨겨진 게시글"(yellow).
- 원문 게시글이 영구 삭제됨(삭제 30일 후) 또는 컬렉션을 찾지 못함: "원문을 찾을 수 없습니다."를 표시하고 스냅샷만 보여 준다.
- 댓글 원문이 삭제됨: 스냅샷만 보여 주고 게시글 이동은 유지한다(게시글이 살아 있으면).
- 스냅샷 필드가 없는 기존 신고(이번 작업 이전 데이터): 스냅샷 영역을 "신고 시점 내용 없음"으로 표시한다. `collectionName`이 없는 기존 게시글·댓글 신고는 `Boards` → `Communities` 순으로 원문을 찾는다.
- 이번 작업 이전에 들어온 채팅 신고: `Chats.reportedAt`이 없어 열람이 거부된다. 배포 시 기존 `Reports`의 `chatId`로 `reportedAt`을 채우는 1회성 스크립트를 실행한다.
- `lastActiveAt`이 없는 유저(배포 후 앱을 열지 않은 유저): `orderBy('lastActiveAt')` 결과에서 빠진다. 유저 목록 하단에 이 사실을 안내하지 않고, 앱을 한 번 열면 목록에 나타난다.
- 관리자에게 `pushToken`이 없음: 그 관리자에게는 보내지 않고 다른 관리자에게는 보낸다. 관리자가 한 명도 없으면 아무 일도 하지 않는다.
- 피신고자가 탈퇴함(`Users` 문서 없음, `DeletedUsers`에 있음): 닉네임 대신 기본 유저 정보(`getDefaultUserInfo`)를 보여 주고, 유저 상세 이동과 정지 해제 행을 그리지 않는다.
- 관리자 본인을 대상으로 한 신고: 일반 신고와 같게 처리한다.
- 숨긴 댓글 때문에 한 페이지가 10개보다 적게 보임: 정상 동작이다. 다음 페이지는 그대로 이어서 불러온다.
- 통계 요청 중 일부 날짜 실패: 실패한 날짜만 "-"로 표시하고 나머지는 보여 준다. 실패한 날짜는 캐시하지 않는다.
