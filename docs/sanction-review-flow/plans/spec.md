# 신고·조치 처리 4단계 목록 - 명세

## 화면/기능 흐름

### 단계 이동

- 새 신고 접수 → 신고가 '검토 필요'에 나타난다(`Reports.resolved == false`).
- '검토 필요' 신고 상세에서:
  - [경고] → 위반 유형 선택 → 확인 → 경고 조치 발급. 조치는 '유저 확인 대기', 근거 신고들은 처리 완료(목록에서 빠짐).
  - [계정 정지] → '계정 정지' 화면(지금 신고가 근거 신고로 미리 선택됨) → 정지 조치 발급. 근거 신고들은 처리 완료. 정지 중에는 관리자가 할 일이 없으므로 조치는 바로 '처리 완료'로 간다.
  - [조치 없이 처리 완료] → 신고만 처리 완료. 조치는 생기지 않는다.
- '유저 확인 대기' 경고:
  - 유저가 경고 화면에서 [정책을 확인했습니다] → '처리 완료'.
  - 유저가 이의 신청 → '답변 필요'.
  - 아무것도 하지 않은 채 이의 신청 기한(조치일 + 30일)이 지남 → 매일 0시 스케줄러가 '처리 완료'로 보낸다.
- '답변 필요' 조치 상세에서 답변 입력 후 [조치 유지] 또는 [조치 취소] → '처리 완료'. 결과 푸시는 지금과 같다.
- '처리 완료' 조치에 유저가 기한 안에 문의 내역에서 이의 신청 → '답변 필요'로 돌아간다.
- 조치 상세의 [조치 취소](이의 신청이 없는 유효한 조치) → 조치 취소(정지 해제, 대상 재공개, 위반 횟수 제외) → '처리 완료'.

### 근거 신고 연결

- 대상이 있는 조치(신고 상세에서 건 경고·정지): 같은 피신고자의 미처리 신고 중 대상이 완전히 같은 것(게시글이면 같은 글, 댓글이면 같은 댓글, 답글이면 같은 답글, 채팅이면 같은 채팅방)을 모두 연결한다.
- 연결된 신고는 `resolved: true`, `sanctionId: {조치 ID}`가 된다. 조치의 `reportIds`에는 연결한 신고 ID가 모두 들어간다.
- 신고 상세는 미처리 상태일 때 '근거 신고 N건'으로 이번 조치에 함께 연결될 신고를 미리 보여 준다(현재 신고 포함).
- 같은 글의 댓글처럼 대상이 다른 신고는 연결하지 않는다. '검토 필요'에 남아 따로 처리한다.
- 계정 정지는 바텀시트가 아니라 별도 '계정 정지' 화면(stack)에서 한다. 위에서부터 위반 유형 6개 선택 목록, 근거 신고, 정지 기간(7일·30일·영구, 정책 권장 안내), 하단 [{기간} 정지하기] 순서다. 위반 유형과 근거 신고를 모두 골라야 버튼이 켜진다.
- 근거 신고 목록: 맨 위 '대상 없음', 그 아래 이 유저가 받은 미처리 신고. 하나만 고를 수 있고, 고른 행은 연한 민트 배경이 된다.
  - 신고를 고르면 그 신고의 대상(게시글·댓글·답글·채팅방)이 정지 대상이 되고, 대상이 같은 미처리 신고만 함께 처리 완료된다. 다른 대상의 신고는 '검토 필요'에 남는다.
  - '대상 없음'을 고르면 대상 없이 정지하고 신고는 연결하지 않는다. 신고 없이 운영자가 모니터링 중 직접 처분하는 경우와 미처리 신고가 없는 유저가 이 경로를 쓴다. 유저 화면에는 '대상' 행 없이 위반 유형과 정책 카드만 보인다.
  - 신고 상세의 [계정 정지]로 들어오면 그 신고가 미리 선택되어 있다. 유저 상세의 [정지]로 들어오면 아무것도 선택되지 않은 상태다.
- 유저에게 보이는 정지·경고 화면에서 채팅 대상은 지금처럼 "채팅"이라고만 표시한다. 채팅방이나 상대(신고자일 수 있음)는 드러내지 않는다.

### 화면

- 관리자 홈의 운영 메뉴: '신고·조치 관리' 하나와 에러 내역. '검토 필요 유저'는 없어진다.
- 유저 목록 위에 검색 입력칸. 닉네임 앞부분이 맞는 유저를 보여 주고, 누르면 유저 상세. 입력칸을 비우면 지금의 최근 활동순 목록.
- 신고·조치 관리: 4개 탭.
  - '검토 필요': 미처리 신고, 최신순. 행을 누르면 신고 상세.
  - '확인 대기', '답변 필요': 해당 단계 조치, 최신순(조치일 기준). 행을 누르면 조치 상세.
  - '처리 완료': 탭 안에 [조치] / [조치 없음] 칩. [조치]는 '처리 완료' 단계 조치, [조치 없음]은 조치 없이 끝낸 신고(누르면 신고 상세, 거기서 [미처리로 되돌리기]).
- 조치 목록 행: 조치 칩(경고·7일 정지·30일 정지·영구 정지), 유저 이름, 위반 유형, 대상 제목(있을 때), 조치일. '답변 필요' 행은 이의 신청 접수일을 함께 보여 준다.
- 조치 상세(지금의 이의 신청 상세를 넓힌 화면):
  - 공통: 조치 내용, 근거 신고 N건(누르면 신고 상세).
  - 이의 신청 없음: '유저 반응'(확인 시각 또는 미확인. 정지는 확인 개념이 없으므로 섹션을 그리지 않는다), 유효한 조치면 하단 [조치 취소].
  - 이의 신청 검토 중: 지금과 같다(답변 입력, [조치 유지]/[조치 취소]).
  - 이의 신청 검토 완료 또는 취소된 조치: 읽기 전용, 하단 버튼 없음.
- 유저 상세의 '조치 이력'은 경고·정지 수 요약과 [조치 이력 보기]만 보여 주고, 목록 화면의 모든 행이 조치 상세로 간다. 조치 이력과 계정 정지 패널은 화면 맨 아래에 있다.

## 상태 정의

| 상태 | 설명 |
| --- | --- |
| 검토 필요 | 신고 `resolved == false`. 아직 아무 조치도 하지 않은 신고 |
| 유저 확인 대기 (`reviewStage: 'awaitingUser'`) | 경고를 걸었고 유저가 확인도 이의 신청도 하지 않음 |
| 답변 필요 (`reviewStage: 'awaitingReply'`) | 이의 신청이 접수되어 관리자 답변을 기다림 (`appeal.status == 'pending'`과 함께 움직인다) |
| 처리 완료 (`reviewStage: 'done'`) | 경고를 유저가 확인함, 경고 확인 기한(30일)이 지남, 정지를 발급함, 이의 신청 결정이 끝남, 조치가 취소됨 |
| 조치 없이 처리 완료 | 신고 `resolved == true`이고 `sanctionId` 없음 |
| 조치로 처리 완료 | 신고 `resolved == true`이고 `sanctionId` 있음. 신고의 진행은 연결된 조치의 단계를 따른다 |

## 엣지 케이스

- 같은 신고자가 같은 유저를 다시 신고: 지금은 기존 신고 문서를 덮어쓰고 `resolved: false`로 돌린다. 기존 신고가 조치에 연결되어 있으면 덮어쓰지 않고 새 신고를 만든다(끝난 조치의 신고가 '검토 필요'로 돌아오지 않게).
- 조치에 연결된 신고의 [미처리로 되돌리기]: 보여 주지 않는다. 되돌리려면 조치 상세에서 조치를 취소한다(취소해도 신고는 처리 완료로 남는다).
- 조치 취소 후 같은 대상에 새 신고: 새 신고는 '검토 필요'에 들어오고, 새 조치를 걸면 새 신고만 연결된다(이미 처리 완료인 신고는 연결 대상이 아니다).
- 신고 상세를 연 뒤 다른 관리자가 같은 대상에 조치: 발급 시 서버가 미처리 신고만 연결하므로 이미 연결된 신고는 건너뛴다. 화면의 '근거 신고 N건'은 다음 조회 때 맞춰진다.
- 경고를 확인하는 순간 이의 신청도 들어옴(다른 기기): 이의 신청 트랜잭션이 `awaitingReply`를 쓰고, 확인 트리거는 `reviewStage == 'awaitingUser'`일 때만 `done`으로 바꾸므로 '답변 필요'가 유지된다.
- 이의 신청 검토 중인 조치의 [조치 취소]: 지금처럼 거부한다. 답변과 함께 [조치 취소]로 결정한다.
- 이번 기능 전에 관리자가 숨긴 글·댓글(조치 문서 없음): 신고 상세에 지금의 [숨김 해제]가 남는다.
- 채팅·프로필 경고: 숨길 대상이 없으므로 경고만 기록한다. 사용자 경고 화면 제목은 "운영 정책 위반으로 경고를 받았습니다"(이전 계획대로).
