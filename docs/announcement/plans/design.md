# 공지사항 설계

## 의도

운영자가 모든 유저에게 알릴 내용을 마켓·커뮤니티 목록 맨 위에 띄운다.

- 당장의 계기: 안드로이드 버전 출시를 기존 iOS 유저에게 알리기
- 지속적인 용도: 거래 매너, 거래 방식 같은 안내를 상시 노출

운영자는 공지를 2~3개만 운영한다. 많아지는 경우는 고려하지 않는다.

## 목표 / 비목표

**목표**
- 마켓 탭·커뮤니티 탭 상단에서 게시 중인 공지가 눈에 띈다.
- 공지를 누르면 전체 내용을 읽을 수 있다.
- 관리자가 앱 안 어드민 페이지에서 공지를 작성·수정·숨김·다시 게시할 수 있다.

**비목표**
- 공지 삭제 (숨김으로 대체)
- 노출 기간 설정·자동 만료
- 공지 개수 제한, 더보기, 공지 전체 목록 화면 (유저용)
- 순서 수동 지정
- 이미지 첨부, 서식(리치 텍스트). 단 본문 URL 자동 링크는 지원한다.
- 푸시 알림, 읽음 처리

**실패로 보는 경우**
- 공지가 거래글 목록 탐색을 방해할 만큼 공간을 차지한다.
- 기존 앱과 다른 시각 언어로 보인다. (기존 컴포넌트·토큰 재사용)

## 용어와 이름

- 사용자 대면 용어: **공지**, **공지사항**, 상태는 **게시 중 / 숨김** (기존 어드민의 게시글 '숨김'·'숨김 해제'와 맞춤)
- 코드 이름은 `Announcement`를 쓴다. `Notice`는 이미 알림 탭(`src/screens/Notice.tsx`)이 쓰고 있어서 충돌한다.

## 화면별 동작

### 1. 마켓·커뮤니티 탭 상단 공지 줄

마켓 탭(`Home`)과 커뮤니티 탭(`Community`) 모두 같은 공지를 같은 모양으로 보여 준다.

- 위치: 거래글 목록의 **머리(첫 줄)**. 목록과 **함께 스크롤되어** 위로 사라진다 (사용자 결정).
  - 마켓·커뮤니티가 함께 쓰는 `PostList`(`src/components/Home/PostList.tsx`)에 목록 머리 영역(`ListHeaderComponent`)을 넣는 경로가 필요하다.
  - 커뮤니티 탭의 카테고리 칩은 지금처럼 목록 밖에 고정되므로, 공지 줄은 칩 아래·첫 게시글 위에 온다 (내 판단).
  - 검색 결과 화면에는 넣지 않는다 (내 판단).
- 한 줄 높이 44px, 좌우 여백 탭 화면 `PADDING`(24)
- 내용: `Badge`(tone `brand`) 안에 Feather `volume-2` 아이콘 + '공지' 텍스트, 그 오른쪽에 제목 한 줄 (넘치면 말줄임). 날짜·개수 표시(`1/3`)는 없다.
- 공지 줄 아래에 높이 8px `bg.secondary` 띠를 화면 양끝까지 둔다.
- 여러 개일 때: 4초마다 다음 공지로 **오른쪽에서 왼쪽으로 부드럽게 슬라이드**한다 (약 450ms, ease-in-out). 마지막 다음에는 첫 공지로 같은 방향으로 이어서 넘어간다(되감기 없음).
- 사용자가 손으로 넘기는 스와이프는 없다. 자동 전환만 한다.
- 공지가 1개면 전환 없이 고정. 게시 중인 공지가 0개면 공지 줄과 띠를 모두 그리지 않는다.
- 탭하면 지금 보이는 공지의 상세로 이동한다.
- 노출 순서: 게시 중인 공지를 **작성일** 최신순. 숨겼다가 다시 게시하거나 수정해도 순서는 바뀌지 않는다 (내 판단).
- 반영 시점: 앱을 다시 열거나 탭에 다시 들어올 때, 당겨서 새로고침할 때 반영되면 충분하다. 실시간 구독은 하지 않는다 (내 판단).
- 로그아웃 상태에서도 보인다.

### 2. 공지 상세

- 스택 화면. 헤더 가운데 제목 **'공지사항'**, 왼쪽 뒤로가기 (기존 스택 헤더 패턴)
- 본문 영역: 제목(title 크기, bold) → 작성일(`2026년 11월 15일` 형식, caption, `text.tertiary`) → 아래 구분선(`border.default`) → 본문(body1, 줄바꿈 유지)
- 본문 안의 URL(`http://`, `https://`)은 자동으로 링크로 인식해 누르면 외부 브라우저·스토어 앱으로 연다 (사용자 결정). 링크는 `text.primaryBrand` 색과 밑줄로 구분한다 (내 판단). 그 밖의 서식은 지원하지 않는다.
- 배지·작성자 표시·댓글·입력창·⋮ 메뉴 없음
- 배경: `assets/images/splash_icon.png`(이미 투명 배경 PNG)를 화면 오른쪽 아래에 크게 깐다.
  - 시안 값: 너비 약 500px, 오른쪽으로 일부 잘려 나감, -12도 회전, 불투명도 0.26
  - 본문이 길어 스크롤해도 잎은 화면에 고정 (내 판단)
  - 다크 모드에서는 불투명도를 낮춘다 (값은 빌더가 기기에서 맞춤)
  - 잎은 장식이므로 터치·접근성 트리에서 제외
- 숨김 처리된 공지나 없는 공지로 진입하면 기존 게시글 상세의 '찾을 수 없음' 처리와 같은 방식으로 안내한다 (내 판단)

### 3. 어드민: 공지 관리

**진입**: `AdminHome`의 '운영' 섹션에 **'공지 관리'** 행(`SettingListItem`) 추가

**목록 화면**
- 기존 material top tab 컴포넌트(신고 관리 `AdminReports`와 같은 형태)로 **게시 중 / 숨김** 두 탭
- 각 행: 제목, 작성일. 최신순
- 새 공지 작성 진입 버튼 (위치는 기존 어드민·목록 화면 패턴을 따름)
- 행을 누르면 수정 화면

**작성·수정 화면**
- 기존 `NewPost`(`PostForm`, `TitleInput`, `BodyInput`) 패턴을 참고한다. 입력은 제목, 본문 두 개.
- **'숨기기' 체크박스** (`expo-checkbox`, 약관 동의 화면과 같은 컴포넌트). 체크 = 숨김, 해제 = 게시 중
- 새 공지는 체크 해제 상태로 시작한다 → 저장하면 바로 게시
- 삭제 버튼 없음
- 검증 규칙(제목·본문 길이 등)은 기존 게시글 폼 규칙을 참고해 빌더가 정한다.

## 제약

- Firestore 요청은 `firestoreRequest` 인터셉터로 감싼다 (`agent_docs/firebase-patterns.md`).
- `firestore.rules`에 새 컬렉션 규칙을 추가한다.
  - 읽기: 모든 사용자(로그아웃 포함)는 게시 중 공지만, 관리자는 전체
  - 쓰기: 관리자만 (`isAdmin()`)
- 리스너를 쓰면 언마운트 시 정리한다. 자동 전환 타이머도 정리한다.
- 색·간격·글자는 `useTheme()` 토큰만 쓴다 (`agent_docs/design-system.md`). 라이트·다크 모두 맞춘다.
- 이 브랜치(`feat/notice`)는 master 기준이다. 진행 중인 `feat/sanction-appeal`이 `AdminHome`, `RootStackNavigator`, `navigationHelpers`, `firestore.rules`를 크게 바꾸므로 병합 시 충돌이 예상된다. 추가는 가능한 한 독립된 블록으로 넣는다.
