# 제재 통지 · 이의 신청 - 명세

화면 문구와 배치는 시안(https://claude.ai/artifact/RRybMR1VfHYg6qgvnKKHvv)의 보드가 기준이다. 정책 배경은 [설계 문서](design.md).

## 화면/기능 흐름

### 관리자 조치

- 유저 상세 [정지] → 정지 바텀시트. 위반 유형·대상 글·기간을 고르고 [N일 정지하기] → 조치 기록 생성, 정지 시작, 사용자 푸시, 유저 상세에 정지 패널(빨간 배경)과 제재 이력 행 추가.
- 정지 바텀시트 '위반 유형' 행 → 위반 유형 선택 화면. 항목을 고르고 [완료] → 메인 시트로 돌아와 선택값 표시. [이전] → 선택 없이 돌아감.
- 정지 바텀시트 기간 세그먼트는 처음에 권장 기간이 선택되어 있고, 아래에 "최근 90일 위반 N회째로, 정책상 {기간}을 권장합니다."를 보여 준다. 관리자는 바꿀 수 있다.
- 신고 상세 [숨기기] → 위반 유형 선택 → 경고 조치 생성, 대상 글/댓글/답글 비공개, 사용자 푸시.
- 정지 중인 유저 상세 [정지 해제] → 정지 즉시 해제, 정지 때 숨긴 다른 글 복구. 위반 대상 글은 비공개 유지. 조치 기록은 유효로 남는다.
- 신고가 들어와도 자동으로 정지되지 않는다. 관리자 푸시만 간다(기존).

### 사용자 경고

- 경고 조치가 생긴 뒤 사용자가 앱을 열면 경고 화면을 한 번 띄운다.
- [정책을 확인했습니다] → 확인 처리 후 닫힘. 다음 실행부터 다시 띄우지 않는다.
- [이의 신청] → 이의 신청 작성 화면.
- [운영 정책 보기] → 운영 정책 화면.
- 대상이 채팅이면 제목 "운영 정책 위반으로 경고를 받았습니다", 대상 글 카드 없음. 대상이 글이면 "이 글은 비공개 처리되었습니다", 댓글·답글이면 "이 댓글은 비공개 처리되었습니다"와 대상 카드.

### 사용자 정지

- 정지 중인 사용자가 앱을 열면 정지 화면만 보인다. 다른 화면으로 이동할 수 없다.
- 정지 화면 상태는 이의 신청 상태에 따라 세 가지(아래 상태 정의).
- [이의 신청] → 이의 신청 작성. [로그아웃] → 로그아웃.
- 정지 기간이 끝나면(0시 스케줄러 또는 관리자 해제) 다음 진입부터 정상 앱.

### 이의 신청

- 작성 화면: 1000자 입력, [제출하기]. 제출 성공 → 정지 화면(검토 중) 또는 문의 내역 상세로 돌아감. 관리자에게 푸시.
- 관리자 이의 신청 상세: 결과 안내 입력란에 답변 작성 → [조치 유지] 또는 [조치 취소].
  - 조치 유지: 답변 저장, 상태 검토 완료, 사용자 푸시.
  - 조치 취소: 답변 저장, 조치 상태 취소(위반 횟수에서 제외), 정지라면 정지 재계산(남은 유효 정지가 없으면 즉시 해제), 대상 글 다시 공개, 사용자 푸시.
- 사용자는 문의 내역(설정 → 문의 내역)에서 모든 조치와 이의 신청 상태·결과를 본다. 결과 푸시를 누르면 해당 항목 상세로 간다.

### 운영 정책

- 경고·정지 화면의 [운영 정책 보기], 관리자 화면에서 연다. 일반 라우트라 로그인 여부와 관계없이 열린다.
- 6개 유형마다 제목, 설명, ✕/✓ 예시. 심각도와 내부 횟수 기준은 보여 주지 않는다.

## 상태 정의

| 상태 | 설명 |
| ---- | ---- |
| 조치 유효 | 기본 상태. 최근 90일 안이면 위반 횟수에 포함 |
| 조치 만료 | 조치일로부터 90일 경과. 횟수에서 제외, 관리자 화면에 '만료' 칩. 저장 값이 아니라 날짜로 계산해도 된다 |
| 조치 취소 | 이의 신청 인용. 횟수에서 제외, 대상 글 공개 |
| 이의 신청 없음 | 정지 화면: 진행 단계 '이의 신청'이 현재, [이의 신청] 버튼 |
| 이의 신청 검토 중 | 정지 화면: 이의 신청 섹션(브랜드색 '검토 중' 칩), 진행 단계 '운영자 검토'에 "보통 3일 안에 검토합니다", [이의 신청 완료](비활성) |
| 이의 신청 검토 완료 | 정지 화면: '검토 완료' 회색 칩, 결과 안내 카드(운영자 답변·답변일), "같은 조치에는 이의를 다시 신청할 수 없습니다." |
| 정지 중 | `Users.report.suspendUntil`이 현재보다 미래. 앱 전체 차단 |

권장 기간: 이번 조치 포함 최근 90일 유효 조치 수가 1회 → 경고, 2회 → 7일, 3회 → 30일, 4회 이상 → 영구. 높음 등급은 1회라도 정지 선택 가능.

## 엣지 케이스

- 이의 신청 중복: 같은 조치에 두 번째 신청 → 서버가 거부. 화면에서는 이미 신청한 조치에 [이의 신청]을 보여 주지 않는다.
- 이의 신청 기한 초과: 기간 정지는 해제일 이후, 경고·영구는 조치일 + 30일 이후 → 버튼 숨김, 서버도 거부.
- 정지 중 새 정지: 조치는 따로 기록, 실제 해제일은 더 늦은 쪽. 정지 화면은 가장 최근 조치를 보여 준다.
- 두 정지 중 하나만 취소: 남은 유효 정지의 해제일로 재계산.
- 정지가 끝난 뒤 검토 중이던 이의 신청: 계속 검토 가능. 결과는 문의 내역에서 본다.
- [정지 해제] 후 남은 이의 신청: 그대로 검토 가능. 조치 취소 시 횟수에서 빠지고 대상 글이 공개된다.
- 대상 글이 이미 작성자에 의해 삭제됨: 조치 기록의 스냅샷으로 제목을 보여 준다. 취소해도 복구하지 않는다.
- 채팅 위반 조치 취소: 숨긴 게 없으므로 기록 상태만 바꾼다.
- 기존 신고 데이터의 옛 카테고리 값: 새 유형으로 매핑해 표시, 모르는 값은 '기타'.
- 사용자가 `Users.report`를 직접 고치려 함: 보안 규칙으로 거부.
- 조치 대상 유저가 탈퇴: 조치·이의 신청 기록은 남기고 관리자 화면에서 '탈퇴한 사용자'로 표시(기존 탈퇴 처리 패턴을 따른다).

## 결정이 필요한 부분

### 채팅 신고에서 경고를 거는 방법

- **지금 상태**: 관리자는 신고 상세의 [숨기기]로 게시글·댓글·답글에 경고를 걸 수 있다. 채팅 신고 상세에는 [숨기기]가 없고(채팅은 숨기지 않음), 유저 상세의 [정지]는 정지만 건다. 그래서 채팅 위반에는 경고를 걸 방법이 없다.
- **왜 막히는지**: spec은 채팅 위반 경고 화면("운영 정책 위반으로 경고를 받았습니다")을 정해 두었지만, 관리자가 그 경고를 만들 수 없다. 채팅 위반은 바로 정지하거나 아무 조치도 못 한다.
- **선택지**
  - A안: 채팅 신고 상세의 조치 패널에 [경고] 행을 추가한다(위반 유형 시트 → 경고, 숨김 없음). 행 제목·설명 문구가 새로 필요하다.
  - B안: 정지 바텀시트의 기간 세그먼트에 '경고'를 추가해 유저 상세에서 대상 없는 경고도 걸 수 있게 한다. 시안의 세그먼트(7일/30일/영구)가 바뀐다.
- **추천**: A안. 채팅 신고에서 근거 신고와 대상 채팅이 함께 기록되어, 이의 신청을 검토할 때 무엇이 위반이었는지 남는다.
