# 전역 키보드 액세서리 설계

## 목표

앱의 모든 iOS 텍스트 입력에서 키보드 위에 완료 기능을 제공한다. 멀티라인 입력의 줄바꿈 동작은 유지하고, 완료를 누르면 키보드를 닫는다.

## 설계

- 이미 설치된 `react-native-keyboard-controller` 1.18.5를 사용한다.
- `App.tsx`에서 전체 앱을 `KeyboardProvider`로 감싼다.
- Provider 내부에 `KeyboardExtender` 기반 `GlobalKeyboardAccessory`를 한 번 배치해 `TextInput`과 `BottomSheetTextInput`에 전역 적용한다.
- iOS 네이티브 `inputAccessoryView` 안에 완료 버튼 하나만 표시한다.
- `KeyboardProvider`의 `preload`를 비활성화해 앱 시작 시 키보드가 순간적으로 노출될 가능성을 줄인다.
- 현재 작업 트리에 있는 `App.tsx`의 스플래시 종료 변경은 그대로 보존한다.

## 트레이드오프와 근거

전역 배치는 화면별 배치보다 코드 중복과 적용 누락이 적어 유지보수성과 확장성이 좋다. 반면 특정 화면에서 다른 구성이 필요해지면 전역 액세서리를 조건부로 비활성화하는 처리가 추가로 필요하다.

`KeyboardToolbar`는 화면 레이아웃을 확보하지 않는 오버레이여서 댓글·채팅 입력을 가릴 수 있으므로 사용하지 않는다. `KeyboardExtender`는 iOS 네이티브 `inputAccessoryView`에 액세서리를 연결하므로 키보드 영역에 포함된다. `returnKeyType="done"` 방식은 멀티라인 입력의 줄바꿈 키와 충돌하므로 사용하지 않는다.

`preload={false}`는 시작 화면의 시각적 안정성을 높이는 대신 첫 키보드 표시가 소폭 늦어질 수 있다. 사용자에게 보이는 시작 화면 깜빡임 방지를 우선한다.

## 운영 및 검증

- TypeScript 타입 검사와 `App.tsx` ESLint를 실행한다.
- 일반·멀티라인·숫자 입력에서 액세서리 표시와 완료 동작을 실제 기기로 확인한다.
- 댓글·채팅 입력이 액세서리에 가려지지 않는지 확인한다.
- 바텀시트 입력에서 툴바 위치와 바텀시트 키보드 처리가 충돌하지 않는지 확인한다.
- 현재 개발 클라이언트에 네이티브 모듈이 포함되지 않았다면 개발 클라이언트를 다시 빌드한다.
