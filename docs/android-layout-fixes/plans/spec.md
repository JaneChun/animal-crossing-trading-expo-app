# Android 레이아웃 이슈 일괄 수정 - 명세

## 화면/기능 흐름

- 회원가입 닉네임·섬 이름 화면: 인풋 포커스 → 키보드가 올라오고, "다음" 버튼이 키보드 툴바("완료") 바로 위에 보이며 누를 수 있다. 키보드를 내리면 버튼이 화면 하단 원래 위치로 돌아온다.
- 게시글 상세: 하단 댓글 인풋 포커스 → 인풋이 키보드 툴바 바로 위에 붙어 보인다. 답글 모드(답글 대상 표시 줄이 인풋 위에 붙은 상태)에서도 답글 대상 줄과 인풋이 모두 툴바 위에 보인다. 키보드를 내리면 인풋이 화면 하단으로 돌아온다.
- 채팅방: 채팅 인풋 포커스 → 인풋이 키보드 툴바 바로 위에 보이고, 마지막 메시지가 인풋에 가려지지 않는다.
- 새 글 작성: 키보드가 없을 때 "아이템 추가"·"등록" 버튼 아래에 `24 + 하단 safe area inset`만큼 여백이 있다. Android에서는 버튼 전체가 시스템 내비게이션 바(3버튼·제스처 모두) 위에, iOS에서는 홈 인디케이터 영역 위에 보인다. 키보드가 올라오면 버튼 영역은 iOS와 마찬가지로 키보드 뒤에 있고, 키보드를 내리면 원래 위치로 돌아온다.
- 인풋 글자 정렬: 회원가입 닉네임·섬 이름 인풋, 프로필 수정 모달의 닉네임·섬 이름·칭호 인풋에서 입력한 글자와 placeholder가 인풋 박스의 세로 중앙에 위치한다.

## 상태 정의

| 상태 | 설명 |
| --- | --- |
| 키보드 닫힘 | 인풋 포커스가 없는 상태. 모든 화면이 수정 전 iOS 레이아웃과 같은 배치여야 한다 |
| 키보드 열림 | 인풋 포커스 상태. 소프트웨어 키보드와 전역 `KeyboardToolbar`("완료")가 함께 보인다 |
| 답글 모드 | 게시글 상세에서 댓글의 "답글" 버튼을 눌러 인풋 위에 답글 대상 줄이 표시된 상태 |

## 엣지 케이스

- iOS: 새 글 작성 하단 버튼 여백을 제외한 모든 화면에서 키보드 열림/닫힘 배치가 수정 전과 같아야 한다. 차이가 보이면 iOS 값이 아니라 Android 분기를 조정한다.
- 내비게이션 모드: Android 3버튼 모드와 제스처 모드는 하단 inset 크기가 다르다. 두 모드 모두에서 새 글 작성 버튼이 가려지지 않아야 한다.
- 글자 크기 확대(접근성): 범위 밖이다. `KEYBOARD_TOOLBAR_HEIGHT`가 고정값이라는 기존 제약(`src/constants/keyboard.ts` 주석)을 그대로 따른다.
- 입력값이 있는 상태: 인풋에 글자가 입력되어 있어도 세로 정렬은 placeholder와 같아야 한다.
