# 에뮬레이터 테스트 데이터 seed 정비 - 명세

## 화면/기능 흐름

- 에뮬레이터가 떠 있음: `npm run emulator:seed` 실행 → Auth 계정, Firestore 문서, Storage 파일을 모두 삭제 → `seed-images/`의 이미지를 Storage에 업로드 → 카탈로그 → 유저(Auth + `Users`) → `Boards`·`Communities` → `Chats`·`Messages` → `Comments`·`Replies` 순서로 저장 → 컬렉션별 생성 개수를 출력하고 exit 0
- 에뮬레이터가 꺼져 있음: `npm run emulator:seed` 실행 → 첫 요청에서 연결 실패 → 오류를 출력하고 exit 1 (운영 DB로 대신 연결하지 않는다)
- 시드 완료 후 `dev:emulator:all`을 Ctrl+C로 종료 → 에뮬레이터가 `emulator-data/`로 export → 다음 `dev:emulator:all` 실행 시 같은 데이터로 시작
- 앱(에뮬레이터 모드)에서 확인할 수 있어야 하는 것:
  - 마켓 탭: 게시글마다 첨부 아이템(`cart`)이 이미지·이름·수량·가격과 함께 표시된다. `buy`, `sell`, `done` 세 종류가 모두 있다.
  - 커뮤니티 탭: 여러 `type`의 게시글이 있고, 카테고리 필터로 걸렀을 때 결과가 나온다. 이미지 없이 주민만 있는 글은 섬네일에 첫 번째 주민 이미지가 보인다.
  - 커뮤니티 게시글 상세: 주민이 지정된 글에는 주민 목록이 이름·이미지와 함께 보인다.
  - 새 커뮤니티 글 작성: 주민 검색(운영 Algolia)으로 고른 주민이 작성 후 상세 화면에도 표시된다.
  - 게시글 상세: 댓글과 대댓글이 보이고, 목록에 표시된 댓글 수가 실제 개수와 같다.
  - 채팅 목록: 채팅방마다 마지막 메시지가 실제 마지막 메시지와 같고, 안 읽은 수가 표시된다.
  - 새 글 작성: 아이템 검색 → 아이템 선택 → 색상(variant) 선택이 동작한다.
  - 알림 탭: 시드된 댓글·대댓글에 대응하는 알림이 읽음·안 읽음 상태로 섞여 보인다.
  - 프로필: 리뷰를 받은 유저의 만족·불만족 수가 실제 `Reviews` 문서 수와 같다.
  - 프로필 사진과 커뮤니티 게시글 이미지가 `seed-images/`에 넣은 이미지로 표시된다. 시뮬레이터와 실기기 모두 같다.
- `.env.local`에 `SEED_MY_UID=<본인 uid>`가 있는 상태로 `npm run emulator:seed` 실행: 1번 시드 유저 자리에 본인 uid가 들어간다 → 앱에서 그 계정으로 로그인하면 1번 유저의 게시글, 채팅, 알림, 리뷰를 본인 것으로 볼 수 있다
- `SEED_MY_UID` 없이 실행: 1번 유저는 기본 uid(`001827.95fe….0427`)로 들어가고, 본인 계정에는 시드 데이터가 연결되지 않는다

## 상태 정의

| 상태 | 설명 |
| --- | --- |
| 전체 시드 | `catalog.json`이 있어 카탈로그와 테스트 데이터를 모두 넣은 상태 |
| 부분 시드 | `catalog.json`이 없거나 Algolia에 연결할 수 없어 카탈로그나 주민을 건너뛰고 나머지만 넣은 상태 |
| 시드 실패 | 에뮬레이터 미실행 또는 저장 중 오류. exit 1로 끝나고 남은 단계는 실행하지 않는다 |

## 엣지 케이스

- `catalog.json`이 없음: "카탈로그 원본이 없어 건너뜁니다"라는 경고와 함께 원본 경로를 출력하고, 테스트 데이터 시드는 계속한다. 이때 게시글 `cart`에 쓰는 아이템 값은 시드 파일에 직접 적은 고정 값을 쓴다(카탈로그 문서가 없어도 게시글 표시는 깨지지 않아야 한다).
- Algolia에 연결할 수 없음(네트워크 없음, 키 없음): "주민 데이터를 가져오지 못해 건너뜁니다"라는 경고와 원인을 출력하고 나머지 시드는 계속한다. 이때 커뮤니티 글의 주민은 표시되지 않지만 게시글 자체는 정상으로 보인다.
- 같은 명령을 두 번 실행: 두 번째 실행도 성공하고, 문서·계정 수가 첫 실행 후와 같다.
- 시드 전에 있던 데이터: 앱에서 직접 만든 계정·게시글·업로드 이미지를 포함해 Auth, Firestore, Storage 데이터가 모두 사라진다.
- `seed-images/users/` 또는 `seed-images/communities/`가 비어 있음: 해당 폴더가 비어 있다는 경고를 출력하고 시드는 계속한다. 이때 `photoURL`은 빈 문자열(앱 기본 프로필 이미지), 커뮤니티 `images`는 빈 배열이 된다.
- 이미지 파일 수가 유저·게시글 수보다 적음: 이름순으로 처음부터 다시 배정해 같은 이미지를 재사용한다.
- 이미지가 아닌 파일(`.gitkeep`, `.DS_Store` 등): 확장자가 `jpg`, `jpeg`, `png`, `webp`인 파일만 업로드한다.
- Mac IP가 바뀜: Firestore에 저장된 이미지 URL의 호스트가 달라 이미지가 깨진다. `.env.local`의 호스트를 고친 뒤 시드를 다시 실행한다.
- 시드 유저의 uid에 점(`.`)이 포함됨(`001827.95fe….0427`, Apple 형식): `unreadCount` 같은 맵 키에도 점이 포함된 원래 uid를 그대로 쓴다.
- 날짜 필드: `createdAt`, `updatedAt`, `lastLogin`은 실행 시각 기준 상대 시간(몇 시간 전, 며칠 전)으로 넣어, 언제 시드해도 목록이 최신순으로 자연스럽게 보이게 한다.
- 시드 유저로는 앱에서 로그인할 수 없다: 앱 로그인은 OAuth → Cloud Function 커스텀 토큰이라, 실제 소셜 계정의 uid로 새 계정이 생긴다.
