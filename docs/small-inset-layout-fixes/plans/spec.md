# 하단 inset이 작은 iOS 기기의 버튼·입력창 가려짐 수정 - 명세

## 화면/기능 흐름

- 새 글 작성, 키보드 닫힘: 화면 진입 → 하단 버튼("아이템 추가"·"등록") 아래 여백은 iOS에서 `max(8, insets.bottom)`, Android에서 `max(8, insets.bottom + 8)`이다. 기기별 값은 아래와 같고, "지금"은 PR #65 적용 상태를 뜻한다.
  - iPhone SE(inset 0): 8. 지금은 0이라 버튼이 화면 아래 끝에 붙는다.
  - iPhone 노치 기기(inset 34): 34로 지금과 같다.
  - Android 3버튼(inset 48): 56으로 지금과 같다.
  - Android 제스처 모드(inset 약 16): 약 24로 지금과 같다.
- 회원가입 닉네임·섬 이름, 키보드 열림: 인풋 탭 → "다음" 버튼 전체가 툴바("완료") 위에 보인다. 버튼 아래 끝과 툴바 위 끝 사이 간격은 iOS 기기의 `insets.bottom`과 관계없이 같고, 그 값은 현재 iPhone 17 Pro에서 보이는 간격이다.
- 게시글 상세 댓글·답글, 키보드 열림: 댓글 입력창 탭 → 입력창 전체(텍스트 필드와 전송 버튼)가 툴바 위에 보인다. 간격은 iOS 기기의 `insets.bottom`과 관계없이 같고, 그 값은 현재 iPhone 17 Pro에서 보이는 간격(계산상 16dp)이다.
- Android의 위 세 화면: 지금 동작(툴바와 8dp 간격, 하단 버튼 여백)을 그대로 유지한다.

## 상태 정의

| 상태 | 설명 |
| --- | --- |
| inset 0 기기 | 홈 버튼이 있는 iPhone(SE 2·3세대 등). `insets.bottom`이 0이다 |
| inset 34 기기 | Face ID iPhone. 기존 식이 이 값을 기준으로 맞춰져 있었다 |
| inset 20 기기 | 홈 버튼이 없는 iPad. `app.config.js`의 `supportsTablet: true`로 지원 대상이다 |

## 엣지 케이스

- iPad(inset 20): 간격이 iPhone과 같아야 한다. 이번 검증은 SE와 17 Pro로 하고, iPad는 SE와 17 Pro의 결과가 같으면 같은 식이 적용되므로 따로 촬영하지 않는다.
- 답글 모드(댓글 입력창 위에 답글 대상 표시가 붙은 상태): 입력창이 높아져도 아래 끝 기준 간격은 같다.
- 키보드 종류(한글·영문, 자동 완성 후보 바 유무)로 키보드 높이가 달라져도 KAV가 실제 키보드 높이를 쓰므로 간격은 같다.
- 글자 크기 확대(접근성): 범위 밖이다. `KEYBOARD_TOOLBAR_HEIGHT`가 고정값이라는 기존 제약(`src/constants/keyboard.ts` 주석)을 따른다.
