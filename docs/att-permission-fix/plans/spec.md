# ATT 권한 팝업 미표시 수정 - 명세

## 화면/기능 흐름

- 첫 설치 후 실행 (iOS): 스플래시 → 온보딩 화면 렌더(권한 요청과 무관하게 진행) → 앱이 `active` 상태가 되고 1초가 지남 → 온보딩 위에 ATT 팝업 단독 표시 → 사용자가 응답 → 알림 권한 팝업 표시 → 사용자가 응답 → 온보딩 계속 사용
  - 스플래시가 1초 넘게 걸리면 ATT 팝업이 스플래시 위에 뜰 수 있습니다. 앱이 `active`이므로 팝업 표시에는 문제가 없습니다.
- ATT 응답 후 (iOS): 허용·거부 모두 Analytics 수집을 켠 뒤, "AdMob 초기화 → 광고 설정 반영"과 "알림 권한 요청"을 동시에 진행합니다. 거부하면 AdMob이 비맞춤 광고를 내보냅니다.
- 광고 설정 반영: AdMob 초기화가 끝난 뒤에 스토어에 반영합니다. 반영되는 순간 홈 목록이 네이티브 광고를 요청하므로, ATT 응답 전에 반영하면 안 됩니다.
- 재실행 (ATT 이미 응답함): 현재 상태를 먼저 확인하고 대기 없이 바로 다음 단계로 진행합니다.
- Android: ATT 단계 없이 바로 알림 권한 요청과 광고 초기화를 진행합니다. 지금과 동작이 같습니다.
- 알림 리스너: ATT 응답과 관계없이 앱 실행 직후 등록합니다. 알림을 탭해 앱을 연 경우의 이동 처리는 지금과 같습니다.
- Analytics: ATT 응답 전에는 수집하지 않습니다. 응답을 받으면 허용·거부와 관계없이 수집을 켭니다.

## 상태 정의

| 상태 | 설명 |
| --- | --- |
| ATT 대기 | 앱이 `active`가 아니거나 지연 시간이 지나지 않아 아직 요청하지 않은 상태 |
| ATT 요청 중 | 시스템 팝업이 떠 있는 상태. 알림 권한 요청과 AdMob 초기화는 이 상태가 끝날 때까지 기다립니다 |
| ATT 완료 | 허용·거부·제한 중 하나로 응답을 받았거나 요청이 실패한 상태. 이후 단계를 진행합니다 |

## 엣지 케이스

- 지연 시간 중에 앱을 백그라운드로 보냄: 요청하지 않고 다시 `active`가 될 때까지 기다립니다.
- ATT 요청이 팝업 없이 `undetermined`로 끝남: 1초 뒤 한 번 더 요청합니다. 두 번째도 `undetermined`이면 다음 단계로 진행합니다.
- ATT 요청이 예외를 던짐: ATT 완료로 처리하고 알림 권한 요청과 광고 초기화를 진행합니다.
- 기기 설정에서 "앱이 추적을 요청하도록 허용"이 꺼져 있음: 시스템이 팝업 없이 거부 상태를 돌려줍니다. ATT 완료로 처리합니다.
- ATT와 알림 팝업은 어떤 경우에도 동시에 요청하지 않습니다.
