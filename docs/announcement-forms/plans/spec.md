# 공지 폼 (Android 테스터 신청 · 의견 보내기) - 명세

## 화면/기능 흐름

### 공통: 공지 상세 하단 버튼과 바텀시트

- 공지 문서의 `form` 필드 값에 따라 공지 상세 하단에 버튼을 고정해서 표시한다. 본문은 그 위에서 스크롤된다
  - `'androidTester'` → '테스터 신청하기'
  - `'feedback'` → '의견 보내기'
  - 없거나 다른 값 → 지금과 같이 본문만 표시
- `form` 필드는 Firestore 콘솔에서 직접 넣는다. 관리자 공지 작성·수정 화면은 이 필드를 읽지도 쓰지도 않는다
  - 관리자 화면에서 그 공지를 수정·저장해도 `updateDoc`이라 `form` 필드는 남는다
- 하단 버튼 탭 → 바텀시트가 열린다
- 시트 헤더: 가운데 제목만 있다. 취소 버튼은 없다
- 시트 맨 아래: 화면 너비 큰 제출 버튼. 입력 영역은 그 위에서 스크롤된다
- 닫기: 시트를 아래로 끌기, 배경 탭, Android 뒤로가기. 닫을 때 키보드도 내린다
- 닫았다가 다시 열면 입력 내용은 비어 있다
- 제출 탭 → 키보드를 내리고 검증 → 저장 요청
- 제출 중 → 제출 버튼 로딩 표시·비활성, 시트는 열린 채 유지
- 성공 → 시트를 닫고 성공 토스트
- 실패(네트워크 등) → 오류 토스트, 시트와 입력 내용 유지
- 입력 검증 시점은 다른 폼과 같이 blur 후, 오류가 난 뒤에는 입력할 때마다 다시 검증. 제출 탭 때도 검증한다

### Android 테스터 신청 (`form: 'androidTester'`)

- 로그인 여부와 관계없이 버튼이 보이고 신청할 수 있다
- 시트 제목 '테스터 신청', 제출 버튼 '신청'
- 시트 본문 (위에서 아래 순서)
  1. 안내 문구: Google Play 스토어에 로그인된 Google 계정 이메일을 입력해 달라는 내용
  2. 이메일 입력칸: 라벨 '이메일', `keyboardType="email-address"`, 자동 대문자·자동 수정 끔
  3. 개인정보 수집·이용 동의 체크박스(필수)와 고지 내용: 수집 항목(이메일), 목적(Android 비공개 테스트 초대), 보관 기간(테스터 모집 종료 후 삭제)
- 동의 체크 해제 상태 → '신청' 비활성
- 저장: 이메일 앞뒤 공백 제거·소문자 변환 → `AndroidTesterEmails/{정규화한 이메일}` 문서 생성
- 성공 후: 하단 버튼이 '신청 완료'로 바뀌고 그 화면에 있는 동안만 비활성. 상세를 나갔다 다시 오면 다시 활성이고, 다른 이메일로 여러 번 신청할 수 있다 (기기에 저장하지 않음)
- 모집이 끝나면 정리하는 임시 기능

### 의견 보내기 (`form: 'feedback'`)

- 버튼은 로그인 여부와 관계없이 보인다
- 비로그인 상태에서 '의견 보내기' 탭 → 시트를 열지 않고 경고 토스트 후 로그인 화면으로 이동 (글 쓰기 버튼과 같은 처리)
- 시트 제목 '의견 보내기', 제출 버튼 '보내기'
- 시트 본문: 짧은 안내 문구 + 여러 줄 의견 입력칸 하나. 개인정보를 받지 않으므로 동의 체크박스는 없다
- 의견 입력칸이 비어 있음 → '보내기' 비활성
- 저장: `Feedbacks` 컬렉션에 자동 ID로 문서 생성 (`uid`, `body`(앞뒤 공백 제거), `createdAt`)
- 성공 후: 하단 버튼은 계속 활성. 여러 번 보낼 수 있다
- 공지를 숨겼다 다시 게시하는 방식으로 계속 운영한다 (정리 대상 아님)

## 상태 정의

| 상태 | 설명 |
| --- | --- |
| 버튼 활성 | 상세 하단 '테스터 신청하기' / '의견 보내기' |
| 시트 입력 전 | 입력 비어 있음. 제출 버튼 비활성 (테스터는 동의 전에도 비활성) |
| 입력 오류 | 입력칸 테두리 오류 색 + 오류 문구 |
| 제출 중 | 제출 버튼 로딩·비활성 |
| 테스터 신청 완료 | 시트 닫힘, 성공 토스트, 하단 버튼 '신청 완료' 비활성 |
| 의견 전송 완료 | 시트 닫힘, 성공 토스트, 하단 버튼 그대로 활성 |

## 데이터·보안

### `AndroidTesterEmails`

- 문서 ID = 정규화한 이메일, 필드 `email: string`(문서 ID와 같음), `createdAt: Timestamp`(서버 시각)
- 규칙: 생성만 허용. 읽기·수정·삭제는 모두 막는다 (관리자 포함, 콘솔은 규칙을 거치지 않음)
- 생성 조건: 필드는 `email`, `createdAt`만, `email`이 문서 ID와 같음, 소문자, 100자 이하, `x@y.z` 형식, `createdAt == request.time`
- 비로그인 허용이므로 `request.auth` 조건은 두지 않는다

### `Feedbacks`

- 자동 ID, 필드 `uid: string`, `body: string`, `createdAt: Timestamp`(서버 시각)
- 규칙: 생성은 로그인 사용자만, 읽기는 관리자만, 수정·삭제 불가
- 생성 조건: 필드는 `uid`, `body`, `createdAt`만, `uid == request.auth.uid`, `body` 1~1000자, `createdAt == request.time`
- 관리자는 당분간 Firestore 콘솔에서 확인한다. 앱 조회 화면은 이번 범위가 아니다

## 엣지 케이스

- 같은 이메일로 테스터 재신청: 문서가 이미 있어 생성이 아닌 수정으로 판정되고 규칙에 막힌다(`permission-denied`). 클라이언트 검증을 통과한 뒤의 `permission-denied`는 중복 외에는 생기지 않으므로, 이 경우 성공과 같이 시트를 닫고 성공 토스트를 띄운다. 오류로 알리면 특정 이메일의 신청 여부가 드러나기 때문이다
- 대문자·앞뒤 공백이 섞인 이메일: 정규화 후 저장하므로 `A@Gmail.com`과 `a@gmail.com`은 같은 신청이다
- Gmail이 아닌 이메일: 형식만 맞으면 받는다. Google 계정은 Gmail이 아닌 주소로도 만들 수 있기 때문이다. 안내 문구로만 Google 계정을 요구한다
- 같은 사람이 다른 이메일로 여러 번 테스터 신청: 막지 않는다 (비로그인 허용의 한계)
- 의견이 공백만 있음: 공백 제거 후 0자로 보고 '보내기' 비활성
- 의견 1000자 초과: 입력칸 아래 오류 문구, 전송하지 않는다
- 시트를 연 채로 로그아웃·세션 만료: 저장이 규칙에 막혀 오류 토스트. 별도 처리하지 않는다
- 키보드: 입력칸에 포커스하면 입력칸이 키보드와 전역 키보드 툴바에 가려지지 않는다 (iOS·Android 모두). 키보드에 덮인 아래쪽 요소(테스터의 동의 체크박스·고지 등)는 키보드가 열린 채로 스크롤해서 닿을 수 있다. 작은 화면(iPhone SE)도 같다. 맨 아래 제출 버튼은 키보드가 열리면 키보드·툴바 위로 올라와 계속 보인다. 여러 줄 의견 입력은 커서를 따라 스크롤된다
- 제출 중 시트를 닫음: 요청은 계속 진행되고, 결과 토스트는 그대로 뜬다. 테스터 신청이 성공하면 하단 버튼이 '신청 완료'로 바뀐다
- 공지가 숨김 처리됨: 상세 자체가 '공지를 찾을 수 없습니다.'로 바뀌므로 버튼도 보이지 않는다
- 하단 버튼 영역: 홈 인디케이터·Android 내비게이션 바에 가려지지 않게 하단 inset만큼 띄우고, inset이 0인 기기에서도 최소 여백을 둔다
- 다크 모드: 모든 색은 테마 토큰. 시트 안 입력칸은 `SheetThemeProvider`가 바꿔 주는 `bg.fill`을 쓴다
